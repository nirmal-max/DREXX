How to run the whole thing

Written in plain words. What sits where, what each file is, what you press, what the second laptop is actually for, and why any of it matters. No prior knowledge assumed.

Part 1 · The map

Two laptops, and what lives on each

Everything below rests on one idea: the two laptops must not be able to stand in for each other. If one person could produce both signatures, the second signature would prove nothing at all.

Laptop A, the worker

This machine. It does the actual work.

  • The tool itself, at D:\akhanda SIH\akhanda\
  • Your signing key
  • The record file it produces
  • The screen you show people

Laptop B, the witness (the LOQ)

Holds one key and answers questions. Nothing else.

  • One small program, node.py
  • Its own separate signing key
  • Its own separate copy of what it signed
  • No case files. None.

The most common misunderstanding

The screen never downloads files from laptop B, because laptop B has no files to give. That is deliberate. If the witness also stored evidence, anyone who broke into it would get the evidence and the key that vouches for it. It holds the key and nothing worth stealing alongside it.

Part 2 · When the frontend arrives

What to send me, and what I will do with it

1

Put her folder somewhere I can read

Anywhere on the D drive is fine. If she sends a zip, unzip it first. Then tell me the folder name. That is all I need to start.

2

I check whether it runs at all

Some frontends need a build step and some do not. I will find out which, run it, and tell you plainly whether it works before we spend time on anything else.

3

I connect it to the real data

Her pages will be showing invented sample data. I replace that with the real record your tool produced, so what a judge sees on screen is the actual output and not a mock-up.

4

I tell you what is missing, honestly

If something she built cannot be connected because the tool does not produce that information, I will say so rather than invent a number to fill the gap.

What I will ask you for

Almost certainly nothing. No accounts to create, no keys to buy, no server to rent. The tool writes files, the page reads files. If her version genuinely needs something extra, I will name it and explain why before you spend anything.

The one question I may ask: whether to keep your current screen as the safe fallback. My answer in advance is yes, keep it, a demo with no working screen is a lost demo, and having two is free.

Part 3 · Running the prototype

The whole sequence, in order

Do these in order. Each one depends on the one before it.

1

Put both laptops on the same hotspot

Use your phone's hotspot, or this laptop's own hotspot. Do not use campus wi-fi. Many campus networks deliberately stop two laptops from talking to each other, even though both have internet, and you will not discover this until the moment you need it.

2

Start the witness on laptop B, and leave the window open

python node.py

You should see Application startup complete. That window must stay open for the whole demo. Closing it stops the witness.

Closing it does not break anything quietly, the tool will refuse to run and will record the refusal. That is correct behaviour, but not what you want on stage.

3

Check laptop A can reach it

curl http://192.168.137.132:8000/witness/pubkey

You want a short line of text back containing a key_id. Nothing back means either the window in step 2 is closed, or laptop B's firewall is blocking it.

4

Do the actual work on laptop A

cd "D:\akhanda SIH\akhanda"
python scripts/demo_bundle.py --witness http://192.168.137.132:8000

About five seconds. This is the step that creates the files. It wipes some files, recovers some files, deliberately tries one job with the witness switched off so you can show it refusing, and writes the certificate.

5

Open the screen

cd "D:\akhanda SIH\console-app"
python -m http.server 8080

Then open http://localhost:8080 in a browser. Click Open chain.json and choose the file the last step made. Put laptop B's address in the witness box and press Connect.

Part 4 · The files

What each file is, in plain words

Everything the tool makes lands in one folder: D:\akhanda SIH\akhanda\demo_bundle\

chain.json The record book. Every action, in order, each one locked to the one before it. This is the file you open on the screen. The main demo

certificate.txt		 The court document. Every line marked with the exact law or standard it answers. Show a judge

One folder you must never share

demo_bundle\_akhanda_home\ contains your private signing key. Never put it on a USB you hand someone, never email it, never upload it. Anyone holding that key can sign records as you.

Part 5 · Why it is built this way

The reasoning, so you can defend it

Why a second laptop

A signature only means something if the person it accuses could not have forged it. Put both keys on one machine and the operator can sign as both. Put the second key on a machine they cannot log into, and the second signature becomes real evidence.

Why it refuses instead of carrying on

If a missing witness simply meant a weaker record, anyone could unplug it and quietly do unwatched work. Because the tool stops and writes down that it stopped, unplugging the witness becomes a way to leave a mark, not a way to avoid one.

Why the check happens first

Wiping cannot be undone. Checking the witness afterwards would be asking permission for something already done. The check happens before a single byte is destroyed.

Why the browser does the checking

If our own program says "this is valid", you are trusting us. When the page recalculates it in front of you, on your own machine, you are trusting arithmetic. A doubter can open the browser tools and watch it happen.

Part 7 · Growth

Where it goes from here

How it grows without getting expensive

  • One witness serves a whole laboratory. Twenty workstations can all send their records to the same second machine. The cost does not rise for each new user, which is exactly how the tools we compete with make their money.
  • The record stays fast as it grows. Tested on five hundred records, a tampered one is found in thirty-seven thousandths of a second. Case files can build up for years.
  • Nothing to install centrally. No server room, no database, no yearly renewal. A laboratory that adopts it is not signing up to a dependency.

The upgrades that would matter most

The honest limit, and why saying it is a strength

The record proves nothing was changed. It cannot prove nothing was hidden before it was ever written down. No ledger in the world can. Recording refusals narrows the gap; nothing closes it.

Say this before a judge asks. A team that names its own limit is believed on everything else. A team caught hiding one is believed on nothing.
